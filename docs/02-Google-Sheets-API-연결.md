# 2. Google Sheets API로 주문 저장하기

일반 API 키는 비공개 시트의 쓰기 권한을 주지 않습니다. 이 실습에서는 서버가 사용할 **서비스 계정**을 만들고, 본인의 시트 하나에 편집 권한을 줍니다. 앱의 `api/orders.js`가 Google Sheets API를 호출합니다. 브라우저에 비밀키를 보내지 않습니다.

Sheets는 이 실습에서 간단한 표 저장소로 씁니다. 일반 데이터베이스의 동시성·고유 키·트랜잭션을 실습한 것으로 설명하지 않습니다.

## 1단계. 내 스프레드시트 만들기
1. [새 Google 스프레드시트](https://sheets.new)를 만듭니다.
2. 문서 제목을 `카페 주문 실습`처럼 정합니다.
3. 왼쪽 아래 첫 탭을 더블 클릭해 **주문내역**으로 바꿉니다. 문서 제목과 탭 이름은 다릅니다.
4. A1을 선택하고 다음 한 줄을 복사해서 붙여 넣습니다. 열 사이는 탭입니다.

```text
주문ID	접수시각(한국)	카페	주문자별칭	메뉴내역	총수량	합계(원)	저장구분
```

`주문내역-머리글.csv`를 가져와도 됩니다. A1:H1이 8개 열로 나뉘었는지 확인합니다. 첫 행 고정과 텍스트 줄바꿈을 켜면 확인하기 편합니다. 비어 있는 시트에는 첫 주문 때 머리글을 자동으로 만들 수도 있지만, 연수에서는 먼저 직접 작성합니다.

5. 주소에서 시트 ID를 복사합니다.

```text
https://docs.google.com/spreadsheets/d/이_부분이_시트_ID/edit
```

주소 전체나 뒤의 `/edit`, `gid` 숫자를 넣지 않습니다. 시트는 전체 공개로 바꾸지 않습니다.

## 2단계. Google Cloud 프로젝트와 API
1. [Google Cloud 콘솔](https://console.cloud.google.com/)을 엽니다.
2. 상단 프로젝트 선택에서 새 실습 프로젝트를 만듭니다.
3. `API 및 서비스 → 라이브러리`에서 **Google Sheets API**를 검색하고 `사용`을 누릅니다.
4. 이 앱은 Drive API, 로그인용 OAuth 동의 화면, 도메인 전체 위임을 사용하지 않습니다.

학교 계정에서 프로젝트 생성이나 키 발급을 막으면 조직 정책일 수 있습니다. 정책을 임의로 해제하지 말고, 사용이 허용된 계정으로 진행하거나 API 연결 부분을 강사 시연으로 전환합니다. 설정이 막힌 상태에서도 체험 모드 배포는 가능합니다.

## 3단계. 서비스 계정과 JSON 키
1. `IAM 및 관리자 → 서비스 계정`에서 `서비스 계정 만들기`를 선택합니다.
2. 이름을 `cafe-order-writer`처럼 정합니다.
3. 이 계정에 Cloud 프로젝트의 소유자·편집자 역할을 부여할 필요가 없습니다. 프로젝트 접근 역할과 사용자 접근 단계는 건너뛰고 완료합니다. 시트 편집 권한은 다음 단계에서 문서에 별도로 부여합니다.
4. 만든 서비스 계정의 상세 화면에서 **서비스 계정 이메일**을 복사합니다. 끝이 `iam.gserviceaccount.com`인 주소입니다.
5. `키 → 키 추가 → 새 키 만들기 → JSON`을 선택합니다.
6. 다운로드한 파일을 **프로젝트 폴더 밖의 개인 보관 위치**에 둡니다. 메모장 등 로컬 편집기로 엽니다. 온라인 JSON 변환 사이트나 채팅에 붙여 넣지 않습니다.

## 4단계. 그 계정에 내 시트 편집 권한 주기
1. 앞서 만든 스프레드시트에서 오른쪽 위 `공유`를 누릅니다.
2. 서비스 계정 이메일을 추가하고 권한을 **편집자**로 지정합니다.
3. 알림 메일 발송 선택이 보이면 끕니다. 서비스 계정은 일반 사람의 메일함이 아닙니다.
4. 링크가 있는 모든 사용자의 편집 권한은 켜지 않습니다. 기존 개인정보가 들어 있는 문서를 공유하지 않습니다.

## 5단계. Vercel 환경 변수 입력
Vercel 프로젝트의 `Settings → Environment Variables`에서 다음 값을 하나씩 추가합니다. 처음에는 **Production**에만 적용하고 Preview·Development는 실제 사용할 때 별도로 설정합니다.

| 변수 이름 | 넣을 값 |
|---|---|
| `GOOGLE_SERVICE_ACCOUNT_JSON` | 다운로드한 JSON 파일의 내용 전체. `{`부터 마지막 `}`까지 그대로 복사합니다. 파일명·경로를 넣는 칸이 아닙니다. |
| `GOOGLE_SPREADSHEET_ID` | 시트 주소의 `/d/` 다음 ID만 입력합니다. |
| `WORKSHOP_CODE` | 동료에게 안내할 실습 코드. 예시를 그대로 쓰지 말고 본인이 정한 8자 이상 문자열을 사용합니다. |
| `GOOGLE_SHEET_NAME` | `주문내역`. 이 이름이면 생략할 수 있습니다. |

JSON 전체를 값에 넣으며 바깥에 따옴표를 덧붙이지 않습니다. JSON 안의 `private_key`에 있는 `\n`은 그대로 둡니다. 변수를 `NEXT_PUBLIC_`, `VITE_` 등 공개 접두사로 바꾸지 않습니다.

실습 코드는 로그인 계정을 대신하는 정식 인증이 아닙니다. 공개 주소에 무작위 쓰기가 들어오는 것을 줄이는 연습용 문턱입니다. 사이트 주소와 코드를 공개 게시판에 함께 올리지 않습니다.

## 6단계. 반드시 다시 배포하기
1. 환경 변수 저장 후 `Deployments`에서 **원격 main의 최신 커밋 배포**를 선택합니다.
2. `Redeploy`로 새 설정을 반영합니다. 오래된 커밋을 재배포하지 않습니다.
3. 완료 후 운영 주소를 새로 열어 **시트 저장 모드**를 확인합니다.
4. 이 표시는 환경 변수가 갖춰졌다는 뜻입니다. 실제 Google 접속과 쓰기 권한 확인은 다음 주문으로 합니다.

## 7단계. 주문 한 건으로 검증하기
1. 메뉴를 담고 `연수생 01` 같은 별칭과 실습 코드를 입력합니다.
2. **주문 내역 저장하기**를 누릅니다.
3. **주문 내역을 시트에 저장했습니다**라는 완료창을 확인합니다.
4. 자신의 시트에서 새 행과 완료창의 주문ID를 대조합니다.
5. `아메리카노 ICE 2개`를 주문했다면 예시 합계가 `7,000원`, 총수량이 `2`인지 확인합니다.
6. 동료에게 내 배포 주소와 실습 코드를 직접 알려 주고, 다른 별칭으로 한 건을 보내게 합니다. 자신의 시트에 별도 행이 생기면 API 연결 실습이 끝난 것입니다.

## 실패하거나 다시 보낼 때
- 저장 실패를 체험 주문 완료로 바꾸지 않습니다.
- 응답이 끊기면 저장은 끝났지만 완료 응답만 못 받았을 수 있습니다. 오류에 나온 주문ID를 시트에서 먼저 검색합니다.
- 같은 내용으로 재시도하면 같은 주문ID를 사용하고, 이미 있는 행을 확인해 추가 저장을 피합니다. 먼저 장바구니·별칭을 바꾸면 새 주문으로 취급합니다.
- 여러 서버가 같은 주문ID를 동시에 확인하고 쓰는 경쟁까지 막는 구조는 아닙니다. 자동 반복 주문이나 대량 부하 테스트를 하지 않습니다. 한 번에 누르지 말고 순서대로 확인합니다.
- 최초에는 전체 주문 열을 읽어 중복을 확인하므로 주문 수가 늘수록 느려집니다. 연수용 소량 데이터에 사용합니다.

## 실습 종료 후
필요한 확인을 끝내면 서비스 계정 키를 삭제하고 시트의 서비스 계정 공유를 해제할 수 있습니다. 그러면 기존 배포의 시트 저장은 중단됩니다. 체험 모드로 되돌리려면 Vercel에서 Google JSON·시트 ID·실습 코드 값을 제거한 뒤 다시 배포합니다. 보관이 필요한 키나 주문 자료를 강사가 대신 삭제하지 않습니다.
