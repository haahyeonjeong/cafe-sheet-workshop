# 연수 진행안

## 시간 배분
코드 제작 대기 시간을 줄이기 위해 완성된 ZIP을 배포한다. 로그인·Git 인증을 사전에 마친 상태에서 첫 배포는 10~15분, Google Cloud와 시트 연결은 별도 20~30분을 목표로 잡는다. 이는 강사 운영안이며 완료 시간 보장이 아니다. 학교 계정 정책이나 권한 승인에 따라 더 걸릴 수 있다.

| 단계 | 연수생이 할 일 | 확인할 결과 |
|---|---|---|
| 로컬 실행 | ZIP 해제 → 최상위 폴더를 Codex 프로젝트로 열기 → ‘로컬로 연결해봐’ | 외부 연결 없는 체험 주문 완료 |
| 첫 배포 | ZIP 해제 → GitHub 커밋·푸시 → Vercel 저장소 연결 | 내 주소에서 체험 주문 완료 |
| 수정 반영 | 메뉴 설명 한 곳 수정 → 커밋·푸시 | 새 배포가 자동 생성되고 문구가 바뀜 |
| 저장소 구성 | 내 시트와 8개 열 만들기 | 주문ID·별칭·내역·합계 열 확인 |
| API 연결 | 서비스 계정 → 공유 → Vercel 환경 변수 → 재배포 | 시트 저장 모드 |
| 최종 확인 | 나와 동료가 순서대로 주문 | 서로 다른 주문ID의 행 2개 |

## 강사 사전 준비
- GitHub·Vercel·Google 계정 로그인과 PC Git 인증 여부를 확인한다.
- 학교 계정의 Cloud 프로젝트 생성·서비스 계정 키 생성·외부 공유 정책을 사전에 확인한다. 정책이 막히면 해당 부분의 시연 경로를 준비한다.
- 연수생 개인별 저장소·Vercel 프로젝트·시트를 사용한다. 강사의 비밀키를 배포 ZIP에 넣지 않는다.
- 강사용 연결본으로 한 건을 주문한 뒤 시트의 주문ID와 금액을 대조한다. 이 자료의 제작 검증은 실계정 연결 검증을 대신하지 않는다.
- 어려움을 겪는 사람을 위해 체험 모드의 첫 배포와 시트 연결의 완료 기준을 나누어 안내한다.

## Codex를 사용하는 순간
기본 코드를 다시 생성할 필요는 없다. 먼저 `public/catalog.js`의 문구 한 곳을 바꾸도록 요청하고 변경 비교를 살펴본다. 그 뒤 본인 저장소에 해당 파일만 커밋·푸시하도록 요청한다. Google 인증키 값은 Codex 채팅에 넣지 않고 Vercel 화면에서 본인이 직접 입력한다.

## 제출할 증거
1. 내 Vercel 주소.
2. GitHub의 첫 커밋과 문구 수정 커밋.
3. Google 시트의 주문ID·별칭·합계 두 행. 인증키·실습 코드·불필요한 개인 정보가 들어간 설정 화면은 캡처하지 않는다.

## 설명할 핵심
GitHub는 코드와 변경 기록을 보관하고, Vercel은 화면과 서버 함수를 실행한다. Google 시트는 주문을 표의 행으로 저장하고, API는 서버가 그 표에 쓰는 통로이다. 네이버 지도 링크는 매장 확인용이며 Naver 검색 API를 호출하거나 메뉴를 자동 수집하는 구조가 아니다.
