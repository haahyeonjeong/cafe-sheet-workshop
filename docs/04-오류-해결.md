# 오류 해결

| 증상 | 먼저 확인할 것 | 해결 방법 |
|---|---|---|
| 첫 화면 404 | Vercel Root Directory·Output Directory | 루트에는 package.json·api·public이 함께 있어야 한다. 출력은 public이다. |
| 화면은 보이는데 서버 연결 실패 | api 폴더 업로드 여부, 배포 로그 | public만 올리지 않았는지 확인하고 프로젝트 전체를 올린다. |
| index.html 더블 클릭 시 빈 화면 | 주소가 file://인지 | Vercel 주소를 열거나 npm start로 실행한다. |
| GitHub 저장소가 Vercel에 안 보임 | 연결된 GitHub 계정·저장소 접근 권한 | 실습 저장소의 접근 권한만 추가한다. |
| 푸시 인증 오류 | GitHub 로그인·저장소 주소 | 본인 계정으로 로그인하고 저장소 권한을 확인한다. 강제 푸시로 해결하지 않는다. |
| 첫 푸시가 거절됨 | 원격에 자동 생성 README 등 기존 커밋이 있는지 | 기존 내용을 확인·보존해 통합한다. 처음 실습이라면 비어 있는 새 저장소를 사용한다. |
| 시트 설정 필요 | Google JSON·시트 ID·실습 코드 중 일부 누락 | 세 항목을 Production에 넣고 최신 main 커밋을 재배포한다. |
| 서비스 계정 JSON 오류 | 전체 내용 복사 여부 | 파일 경로나 비밀키만 넣지 말고 JSON 전체를 넣는다. 바깥 따옴표를 추가하지 않는다. |
| Google 인증 실패 | 키 유효성·키 내용의 줄바꿈 | 원본 JSON 내용을 그대로 다시 입력한다. 삭제된 키는 사용할 수 없다. |
| 쓰기 권한 오류 | Sheets API 사용 설정·시트 공유 | 같은 Cloud 프로젝트에서 API를 켜고 JSON의 client_email에 시트 편집자 권한을 준다. |
| 시트를 찾지 못함 | 문서 ID·탭 이름 | gid 대신 /d/ 다음 ID를 넣고 탭을 주문내역으로 바꾼다. |
| 머리글 오류 | A1:H1의 실제 값 | 제공한 8개 머리글을 정확히 붙인다. 기존 자료가 있는 시트를 덮어쓰지 않는다. |
| 실습 코드 오류 | 공백·Vercel 설정 환경·재배포 | 코드 양끝 공백을 지우고 설정한 값과 일치시키며 재배포 여부를 확인한다. |
| 값은 넣었는데 계속 체험 모드 | 환경 변수 적용 범위·구 배포 주소 | Production 설정과 새 배포의 운영 주소를 확인한다. Preview 주소는 별도 환경을 쓴다. |
| 너무 많은 요청·429 | 짧은 시간에 반복 주문했는지 | 잠시 기다린 뒤 한 번씩 요청한다. 학교 전체가 한 서비스 계정을 공유하면 할당량을 함께 쓴다. |
| 저장 결과 불확실·시간 초과 | 시트의 주문ID 검색 | 먼저 존재 여부를 확인한다. 같은 내역으로 재전송하면 같은 ID를 사용한다. 중복 행을 자동 반복 전송으로 해결하지 않는다. |
| Cloud 키 생성·외부 공유 불가 | 학교 조직의 제한 | 정책을 임의로 완화하지 않고 허용된 계정 또는 강사 시연으로 전환한다. |

## 설정을 되돌리는 방법
체험 모드로 돌아가려면 Vercel의 Google JSON·시트 ID·실습 코드 값을 모두 제거하고 최신 main을 재배포한다. 일부만 남기면 실수로 저장한 것으로 착각하지 않도록 설정 오류를 표시한다.

코드 수정이 잘못되었으면 Git의 변경 비교로 해당 부분을 확인하고 이전 검증 내용을 새 커밋으로 되돌린다. 이력을 강제로 재작성하지 않는다. 비밀키가 GitHub에 올라갔다면 코드에서 지우는 것만으로 해결되지 않는다. 해당 키를 폐기하고 새 키를 만든 뒤 Vercel 값도 교체한다.

## 운영상 한계
실습 코드를 아는 사람은 별칭을 바꾸어 여러 주문을 보낼 수 있다. 요청 제한·계정 인증·결제·매장 알림은 구현하지 않았다. 같은 ID의 동시 요청까지 원자적으로 막지 않는다. Google 시트 쓰기를 일반 DB 구축이나 실제 주문 접수 시스템과 동일하게 설명하지 않는다.
