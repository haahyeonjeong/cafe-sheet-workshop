# 검증 기록

## 외부 연결 없는 로컬 실행 요청 반영

- `npm start`는 `.env.local`을 읽지 않는다. 로컬 서버가 기존 Google 인증정보·시트 ID·실습 코드 환경 변수를 지우므로 항상 체험 모드로만 실행한다. 실제 외부 서버·DB·계정은 연결하지 않았다.
- 잘못된 가짜 Google 연결 환경 변수를 주입하고 첫 포트를 점유한 상태에서 실제 로컬 서버를 실행했다. 다음 포트 자동 선택, 설정 API의 demo·실습 코드 미요구, 임자떡 쿠키 2,500원 체험 주문 성공, 사진 응답, 비공개 파일 접근 차단을 한 테스트로 확인했다. 원래 주문 처리 테스트 19개도 통과했다.
- ZIP 최상위에 package.json·AGENTS.md·public·api가 바로 나오도록 구성했다. Codex는 ‘로컬로 연결해봐’ 요청을 받으면 AGENTS.md에 따라 실행과 체험 주문을 확인한다.

## 확인한 범위
- JavaScript 10개 파일의 문법과 package.json·vercel.json을 확인했다.
- Node 기본 테스트 19개를 통과했다. 가격 위조, 옵션·수량·별칭·주문ID 검증, 한국 시각, 체험/설정 오류 구분, 실습 코드, 다른 출처 요청, 서비스 계정 JWT 서명, RAW 쓰기, 중복 주문ID 확인, 충돌·권한·할당량·네트워크 실패를 검증했다.
- 테스트는 일회용 RSA 키와 가짜 Google 응답을 사용했다. 실제 인증정보를 파일에 저장하거나 출력하지 않았다.
- 실제 메뉴 JPEG 8장을 public/images에 포함했고 각 파일의 형식·경로·대체 텍스트를 확인했다.
- 브라우저에서 8장의 로딩 완료와 원본 크기 1280×960을 확인했다. 메뉴와 사진의 일치 여부를 원본 상품명과 비교했다.
- 메뉴가 8종으로 작고 사진 합계가 약 1MB이므로 모두 즉시 불러오도록 했다. 최종 확인에서도 8장 모두 로딩 완료 상태를 확인하고 캡처했다.
- 내장 브라우저에서 검색·검색 결과 없음·디저트 분류·온도 선택·메뉴 담기·수량·삭제·빈 별칭 오류·모바일 주문 내역 이동·체험 주문 완료를 확인했다.
- 별도 로컬 서버에서 잘못된 실습 코드를 넣으면 차단되고, 올바른 코드로 다시 보내면 체험 주문이 완료되는 것을 확인했다. 중복 오류 문구는 한 곳에만 나타나도록 수정했다.
- 사진 추가 후 8종 각 1개의 합계 34,000원을 확인했다. 서버를 최신 카탈로그로 재시작하고 임자떡 쿠키 1개의 완료 문구와 2,500원을 다시 확인했다.
- PC 1280px와 모바일 390px에서 화면을 확인했다. 사진 추가 전 320px에서도 가로 넘침이 없음을 확인했다. 사진 추가 후 390px에서는 문서 너비 375px로 390px 뷰포트를 넘지 않았다. 차이는 세로 스크롤바 공간이다.
- 브라우저의 오류·경고 로그가 없는 것을 확인했다. 키보드 포커스와 기본 dialog의 초점 이동을 관찰했다.

## 화면 비교
목표 이미지 생성 도구는 404 오류를 반환했다. 목표 이미지를 생성했다고 주장하지 않고, 제공된 참고 화면과 Design.md를 기준으로 비교했다.

| 비교 항목 | 확인 결과 |
|---|---|
| 매장 정보 | 실제 네이버 검색 결과와 참고 앱의 매장명·주소를 확인했다. |
| 배치 | PC는 메뉴와 주문 내역 두 열, 모바일은 한 열과 주문 내역 이동 버튼이다. |
| 글자 | 매장명·메뉴명·금액·버튼의 위계를 확인했다. 작은 화면에서 조작 영역을 유지한다. |
| 색상·여백 | 크림색 바탕·흰 표면·녹색 강조, 기존 간격과 표면을 유지했다. |
| 사진 | 후속 요청에 따라 실제 사진 8장을 추가했다. 원본 비율을 유지하고 상품이 잘리지 않는지 확인했다. |
| 문구 | 예시 가격·실습용 주문·체험 모드·시트 저장 모드·저장 실패를 구분했다. |
| 흐름 | 입력 → 장바구니 → 전송 → 서버 합계 → 완료창을 확인했다. |

예정에 없던 홍보 문구나 기능은 추가하지 않았다. 사진을 추가하면서 이미지와 맞지 않는 초코 쿠키 한 항목만 사용자 선택에 따라 임자떡 쿠키로 바꾸었다. 바닐라라떼·딸기라떼 사진의 원본 상품명은 각각 바닐라빈라떼·딸기밭라떼이며 출처와 대체 텍스트에 구분해 적었다.

실제 캡처: [PC 화면](주문화면.png), [모바일 화면](주문화면-모바일.png), [주문 완료](주문완료.png). 이미지와 구현 명세를 직접 확인했으며, 생성하지 못한 목표 이미지와 완전히 일치한다고 평가하지 않는다.

## 아직 확인하지 않은 범위
- 연수생의 Google 계정·서비스 계정 키로 실제 Google API에 접속해 행을 쓰는 작업은 하지 않았다. 인증정보 입력 후 안내서 7단계로 검증해야 한다.
- 새 GitHub 저장소 생성·원격 푸시·Vercel 원격 배포는 하지 않았다. 사용자가 연수생에게 수행하게 할 실습 단계로 남겼다. Ready와 운영 주소의 커밋 일치는 실제 배포 때 확인한다.
- 여러 서버에서 같은 주문ID가 동시에 들어오는 경우의 정확한 1회 저장, 대량 주문, 정식 사용자 인증, 결제는 구현하지 않았다.
- 시트의 기존 주문 목록을 읽어 중복을 확인하므로 데이터가 많아질수록 읽기 비용·응답 크기가 늘어난다. 소규모 연수용으로 제한한다.
- 실제 프린터·화면 읽기 프로그램의 별도 검증은 하지 않았다. 인쇄용 스타일은 기본 제공한다.

## 용량과 보관
외부 패키지 설치·node_modules 복사·전체 프로젝트 백업을 하지 않았다. 최종 ZIP에는 소스·안내서·실제 메뉴 사진·필요한 화면 검증 자료만 넣고 work와 비밀정보를 제외한다. 중복 다운로드와 사용이 끝난 작업 파일은 Windows 휴지통으로 정리한다. 휴지통 이동을 디스크 공간 확보로 표현하지 않는다.

원본 URL 중간 목록과 중복 전체 화면 캡처는 work에서 총 209,756바이트를 휴지통으로 보냈고 원래 위치에서 없어진 것을 확인했다. 브라우저 도구가 만든 사진 다운로드 임시 폴더 4개는 확인 시 이미 없었다. 최종 메뉴 사진 8장과 PC·모바일·완료 캡처 3장은 보관했다. 정리 상세 기록은 제작용으로만 남기고 연수생용 ZIP에서는 제외한다.
